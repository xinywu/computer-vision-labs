# 实验四编码规范与设计走查记录

## 1 Python 编码规范

### 1.1 命名规范

- 文件名使用小写字母和下划线，例如 `edge_segmentation.py`。
- 函数名使用小写字母和下划线，例如 `read_gray`。
- 普通变量使用小写字母和下划线，例如 `gradient_x`。
- 常量使用全大写字母和下划线，例如 `DATA_DIR`。
- 文件名应能说明文件内容，不使用 `test1.py`、`new.py` 等含义不明确的名称。

### 1.2 注释规范

- 使用中文注释说明关键处理步骤。
- Python 单行注释使用 `#`，不使用 `//`。
- 不给含义明显的代码添加重复注释。
- 对算法参数、异常处理和容易出错的位置进行说明。
- 修改代码后同步修改已经失效的注释。

### 1.3 代码格式

- 每一级缩进使用 4 个空格，不使用 Tab。
- 运算符两侧保留空格。
- 函数之间保留两个空行。
- 导入语句放在文件开头，标准库和第三方库之间空一行。
- 单行代码不宜过长，复杂调用可使用括号合理换行。

### 1.4 函数设计

- 一个函数只负责一项主要功能。
- 函数名应明确表示其作用。
- 重复使用的保存和读取操作应封装为独立函数。
- 图像处理函数通过参数接收图像，不在函数内部重复读取文件。
- 主函数负责组织执行顺序，不包含过多具体算法代码。

### 1.5 文件组织

- 原始图片放在 `data` 文件夹。
- Python 源码放在 `src` 文件夹。
- 实验结果放在 `results` 文件夹。
- 设计和报告文档放在 `docs` 文件夹。
- 运行截图和测试证据放在 `evidence` 文件夹。
- 不在源码目录中保存实验结果图片。

### 1.6 异常处理

- 读取图片后必须检查结果是否为空。
- 保存图片后必须检查返回值。
- 错误信息应包含发生问题的文件路径。
- 不使用空的 `except` 隐藏程序错误。
- 参数必须满足 OpenCV 的要求，例如自适应阈值的邻域大小必须为奇数。

## 2 设计走查方法

走查时重点检查以下内容：

1. 函数输入和输出是否清楚。
2. 是否处理了图片读取和保存失败。
3. 算法参数是否符合 OpenCV 的要求。
4. 文件和函数职责是否清晰。
5. 代码实现是否与详细设计一致。
6. 实验结果是否足以支持报告中的分析。

### 走查意见 1

发现问题：

原设计如果直接使用相对路径 `data/photo01.jpg`，程序只能在固定目录下运行，从其他目录启动时可能找不到图片。

修改建议：

根据 `__file__` 获取源码位置，再定位实验目录、数据目录和结果目录。

处理结果：

已使用 `Path(__file__).resolve().parents[1]` 获取实验目录，使程序不依赖终端当前路径。

### 走查意见 2

发现问题：

图片读取失败时，OpenCV 通常只返回空值。如果不检查，后续算法会产生难以理解的错误。

修改建议：

封装统一的图片读取函数，读取后检查结果，并在错误信息中显示完整路径。

处理结果：

已在 `read_gray` 函数中检查图片是否成功读取，失败时抛出 `FileNotFoundError`。

### 走查意见 3

发现问题：

只保存三组 Canny 结果，难以直观看出阈值变化造成的差异。

修改建议：

除分别保存结果外，再生成一张水平拼接的对比图，并计算每组结果的边缘密度。

处理结果：

已生成 `canny_comparison.jpg`，并在终端输出三组阈值对应的边缘密度。

### 走查意见 4

发现问题：

Sobel 梯度包含正值和负值，如果直接转换为 `uint8`，负值会丢失，可能导致结果异常。

修改建议：

先根据 x、y 梯度计算梯度幅值，再归一化到 0～255。

处理结果：

已使用浮点类型计算梯度幅值，并在保存前完成归一化和类型转换。
