# 需求评审与 MVP 范围

## 1. 评审依据

本次评审以实验一的需求规格为基础，从核心价值、实现成本、使用频率和异常风险四个方面重新确定需求优先级。

优先级分为：

- MVP：本阶段必须实现并验收。
- 可推迟：有实际价值，但不影响基础流程运行。
- 删除：与当前项目目标无关，不再纳入范围。

## 2. 需求评审结果

| 编号 | 需求概要 | 评审结果 | 评审理由 |
| --- | --- | --- | --- |
| FR-01 | 通过命令行接收输入和输出路径 | MVP | 是程序能够处理不同图片的基础入口。 |
| FR-02 | 读取图像并输出 shape、dtype 和通道数 | MVP | 用于确认输入数据是否符合处理条件。 |
| FR-03 | 将 BGR 彩色图转换为灰度图 | MVP | 是后续图像处理实验的基础功能。 |
| FR-04 | 灰度图输入可以直接保存 | 可推迟 | 属于兼容性增强，不影响彩色图像主流程。 |
| FR-05 | 自动创建不存在的输出目录 | MVP | 可以避免因目录缺失导致保存失败。 |
| NFR-01 | 处理 1920×1080 图像不超过 2 秒 | MVP | 保证基础处理具有可接受的运行效率。 |
| NFR-02 | 记录依赖和复现步骤 | MVP | 保证其他同学可以配置并运行项目。 |
| NFR-03 | 路径不写死且代码结构清楚 | MVP | 便于后续实验继续扩展功能。 |
| EX-01 | 输入不存在或损坏时明确报错 | MVP | 是最常见的输入异常，必须处理。 |
| EX-02 | 不支持的图像形状给出错误信息 | 可推迟 | 特殊通道和维数出现频率较低，可后续完善。 |

本轮没有删除需求。现有需求均与基础图像处理程序有关，其中两项兼容性需求调整为可推迟。

## 3. MVP 范围

MVP 应能够接收输入和输出路径，读取正常彩色图像，输出图像属性，将图像转换为灰度图，自动创建输出目录并保存结果；程序还应处理常见的读取和保存错误，记录运行依赖，并在指定测试平台上满足基本性能要求。

## 4. 预评审意见

1. MVP 应优先保证“读取、检查、灰度转换、保存”这一条完整主流程，不在当前阶段加入图形界面和实时摄像头处理。
2. 自动创建输出目录属于实现成本较低但能明显改善使用体验的功能，建议保留在 MVP 中。
3. 灰度图兼容和特殊图像形状处理可以推迟，但应在文档中明确当前支持的输入类型。
4. 性能要求需要写明测试图像尺寸和测试环境，否则不同设备上的结果无法直接比较。
